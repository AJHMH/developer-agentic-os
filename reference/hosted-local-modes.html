Quick reference

Hosted and local modes

The application has two deliberately different shells and two persistence stories. Identify the mode first; only then follow the request.

Mode selector

src/app/page.tsx

process.env.VERCEL === "1"
  -> HostedCommandCentre
else
  -> CommandCentreShell

The hosted path is the deployed, authenticated experience. The local path is the unauthenticated repository-oriented experience intended to work with zero hosted configuration.

Request paths

HostedhostedIdentity authenticates the request and resolves the Clerk organization as the tenant boundary.
WorkspaceThe request is checked against the tenant workspace before domain operations run.
PersistenceReads and writes pass through hosted persistence, normally Neon-backed JSON state.
LocalrepositoryContextForRequest resolves the repository and context from request input.
WorkspaceThe repository root and local store are initialized from the filesystem.
PersistenceState is read and written as local JSON files.

The rule to remember

Mode is not just a visual theme. It changes the shell, authentication boundary, workspace lookup, and persistence provider. When debugging, start by asking: “Am I on the hosted path or the local path?”

Important exception

In development and test, HOSTED_JSON_FIXTURE_MODE=true can substitute fixture-backed hosted behavior. That is still the hosted conceptual path; only the persistence implementation is replaced for repeatable local testing.
