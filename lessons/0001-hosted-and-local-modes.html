Lesson 01 · Application architecture

One application, two runtime stories

Your first win is being able to classify a request before you trace it. This lesson takes about five minutes.

1. Start at the mode boundary

Open src/app/page.tsx. The page chooses between two command-centre components: 

process.env.VERCEL === "1"
  -> HostedCommandCentre
else
  -> CommandCentreShell

That decision predicts the rest of the request. Hosted mode is the deployed product path, with Clerk authentication and tenant-scoped hosted state. Local mode is the repository-local path, with a filesystem-backed store and no requirement for hosted credentials.

2. Trace the first meaningful boundary

Hosted requestStart at src/app/api/hosted/_shared.ts. hostedIdentity authenticates and resolves the tenant workspace.
Local requestStart at src/server/workspace/request-context.ts. repositoryContextForRequest resolves repository and context input.
Storage boundaryHosted writes delegate through the hosted provider; local writes use writeJsonFile.

Do not merge these paths mentally. A bug in local JSON persistence does not automatically say anything about Neon persistence, and a hosted authorization problem may have no local equivalent.

3. Retrieve, do not reread

Pause before looking at the answer. Which path would you inspect first?

  1. The deployed command centre shows a tenant access error.
  2. A local task disappears after the process restarts.
  3. A test needs deterministic hosted behavior without a live database.
Check your answer
  1. Hosted path: hostedIdentity, workspace access, then hosted persistence.
  2. Local path: local store initialization and writeJsonFile.
  3. Hosted conceptual path with HOSTED_AUTH_FIXTURE_MODE=true to bypass authentication. Development and test-only hosted JSON persistence uses HOSTED_JSON_FIXTURE_MODE=true separately.

4. Primary reading

Read the short official Next.js environment variables guide, then compare its general principles with this repository's mode switch in src/app/page.tsx.
